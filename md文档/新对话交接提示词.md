   - Service：业务规则、权限、事务、事件发布。禁止返回 HTTP 状态细节。
   - Mapper：只做 SQL 和映射。**禁止先按 ID 查全表再在 Java 内存里过滤 userId。**

2. 所有 SQL 必须显式带 user_id：
   更新删除一律 WHERE id = #{id} AND user_id = #{userId}。XML 禁止 SELECT *，
   只允许 #{} 占位，禁止字符串拼接。
   diary_tag 没有 user_id，所以涉及它的查询必须 JOIN diary 带 user_id 条件；
   推荐 INSERT ... SELECT ... WHERE d.user_id = #{userId}，把权限校验放进 SQL。

3. 越权一律返回 404 / 40401，不用 403 —— 防止攻击者枚举出"哪些 ID 真实存在"。

4. 统一响应 {code, message, data, timestamp}；字段用 snake_case，但**不用全局
   SNAKE_CASE 策略**，而是在字段上显式 @JsonProperty（这是刻意决定，别"优化"掉）。

5. 错误码字典（已实现，新增要同步 ErrorCode 枚举）：
   0 成功 / 40001 参数 / 40101 未登录 / 40301 无权限 / 40401 资源不存在 /
   40501 方法不支持 / 40901 冲突 / 42201 无法处理 / 50011 AI或向量服务失败(→HTTP 502) /
   50001 未知

6. 分页：page 从 0 开始，Service 层强制 size <= 100。

7. 时间：数据库统一存 UTC，接口返回 ISO-8601，前端只能用 src/utils/formatTime.ts 格式化。

8. 日志绝不打印：日记正文、密码、Cookie、API Key、Prompt 内容。

9. 迁移脚本已执行过就**永不修改**，要改就加 V2__xxx.sql。迁移只由我写。

10. 前端：src/api/request.ts 是唯一 axios 实例；页面只做展示和交互；
    跨页面状态进 Pinia；40101 时清 store 并跳 /login；
    所有异步按钮要有 loading + 防重复提交；删除类操作要二次确认。
