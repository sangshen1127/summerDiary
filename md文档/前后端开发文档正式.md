# AI 日记系统前后端开发文档

版本：V1.0  
适用范围：Spring Boot 后端、MyBatis 持久层、Vue 3 前端、数据库、部署与开源工程化  
配套文档：[AI Agent 开发文档](./AI-Agent-开发文档z%20han.md) · [正式开发文档](./AI日记系统开发文档.md) · [开发模式文档](./AI日记系统开发模式文档.md)

## 1. 文档定位和技术决策

本文件把用户提供的两份参考资料整理成前后端团队可以直接执行的工程文档。参考资料中的示例、Yusi 借鉴建议和“可以直接给编程 AI 的总指令”是需求背景，不代替本项目的接口、代码和验收标准。

参考资料有一处技术栈差异：其中一份推荐 JPA + React，另一份明确给出 MyBatis + Vue 3 全家桶专项规范。本项目采用后者作为实施基线：

- 后端：Java 21、Spring Boot 3.x、Spring Web、Spring Security、MyBatis、MySQL 8。
- AI：LangChain4j，通过独立的 AI Service 接入；具体 Agent 规则见配套文档。
- 前端：Vue 3、TypeScript、Vite、Vue Router、Pinia、Axios、Element Plus 或 Tailwind CSS、Tiptap（可选）。
- 部署：Docker Compose；MVP 启用 MySQL 和 Chroma，Redis 后置。

## 2. 产品目标与范围

### 2.1 第一版核心闭环

```text
注册/登录
  -> 创建日记
  -> MySQL 保存
  -> 异步 AI 分析
  -> Recent Memory / Long-term Profile / Semantic Memory
  -> AI Chat 检索历史
  -> 用户查看和治理记忆
```

传统日记功能包括注册、登录、创建、修改、删除、列表、详情、日期筛选、关键词搜索、标签和心情。AI 功能包括摘要、情绪/主题/实体提取、近期记忆、长期画像、语义检索和对话。

### 2.2 第一版明确不做

社交广场、陌生人匹配、MCP Gateway、复杂 Agent Runtime、多模型控制平面、多人情景室、大规模 Life Graph 和复杂地理轨迹。它们可以进入后续路线图，但不能阻塞第一版闭环。

### 3.1 分层规则

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| Controller | 参数校验、认证上下文、调用 Service、统一响应 | SQL、Prompt、直接调用模型 |
| Service | 业务规则、权限判断、事务、事件发布 | HTTP 状态细节 |
| Mapper | MyBatis SQL 和结果映射 | 业务决策、跨用户过滤后的二次判断 |
| Event/Task | 异步调度、状态、重试和幂等 | 修改无关业务数据 |
| AI Service | Prompt、模型调用、结构化解析、上下文 | 绕过 Service 读取全库 |
| Frontend API | HTTP 封装、类型、错误转换 | 在页面散落业务规则 |
| Store | 跨页面状态和请求状态 | 代替后端做权限或持久化规则 |

所有涉及用户数据的 SQL 都必须显式带 `user_id`。更新和删除使用 `WHERE id = #{id} AND user_id = #{userId}`，禁止先按 ID 查询全部数据再在 Java 内存中过滤。

## 5. 后端模块设计

### 5.1 模块清单

| 模块 | 核心类 | 职责 |
| --- | --- | --- |
| Auth | `AuthController`, `AuthService`, `UserMapper` | 注册、登录、退出、当前用户 |
| Diary | `DiaryController`, `DiaryService`, `DiaryMapper` | 日记 CRUD、分页、筛选、标签关联 |
| Tag | `TagController`, `TagService`, `TagMapper` | 用户标签和关系维护 |
| AI | `AiChatController`, `CognitionService`, `AiClient` | 分析、对话、结构化输出 |
| Memory | `MemoryController`, `MemoryService` | 查看、修改、禁用、删除、来源 |
| Profile | `UserProfileController`, `UserProfileService` | 长期画像读取和用户修改 |
| Task | `AiTaskService`, `AiTaskWorker` | 异步任务、重试、幂等、错误 |
| Export | `ExportController`, `ExportService` | JSON/ZIP 导出和删除 |

### 5.2 关键调用链

```text
DiaryController
  -> DiaryService.create(userId, request)
      -> 校验标签和输入
      -> DiaryMapper.insert
      -> 发布 DiaryCreatedEvent
  -> 返回 DiaryResponse

AiTaskWorker
  -> CognitionService.analyze(task)
  -> MemoryService.apply(changeSet)
  -> EmbeddingService.index(source)
  -> AiTaskMapper.markSuccess
```

日记正文保存和 AI 任务创建在同一业务事务内完成；事件使用 `@TransactionalEventListener(phase = AFTER_COMMIT)` 或事务型 Outbox 在提交后投递，模型调用在事务外异步执行，避免 Worker 读取未提交数据或长时间持有数据库事务。

## 6. 数据库设计

### 6.1 核心表

| 表 | 关键字段 | 约束和索引 |
| --- | --- | --- |
| `user` | `id, username, password_hash, status, created_at` | `username` 唯一 |
| `diary` | `id, user_id, title, content_ciphertext, mood, weather, location, created_at, updated_at` | `(user_id, created_at)` |
| `tag` | `id, user_id, name` | `(user_id, name)` 唯一 |
| `diary_tag` | `diary_id, tag_id` | 联合主键 |
| `diary_analysis` | `id, diary_id, summary, emotion_json, topics_json, entities_json, schema_version` | `diary_id` 唯一 |
| `memory` | `id, user_id, type, summary, importance, confidence, source_diary_id, status, origin, version, expires_at` | `(user_id, type, status)` |
| `user_profile` | `user_id, interests_json, goals_json, habits_json, summary, version, updated_at` | `user_id` 唯一 |
| `ai_conversation` | `id, user_id, title, created_at, updated_at` | `(user_id, updated_at)` |
| `ai_message` | `id, conversation_id, role, content, citations_json, created_at` | `(conversation_id, created_at)` |
| `ai_task` | `id, user_id, source_type, source_id, task_type, status, retry_count, error_code, idempotency_key` | `idempotency_key` 唯一 |

### 6.2 建表和迁移

- 使用 Flyway 或 Liquibase 管理 `V1__init.sql`、`V2__ai_analysis.sql` 等迁移脚本。
- 生产和本地启动都执行同一套迁移，禁止依赖手工建表。
- JSON 字段使用 MySQL `JSON` 类型；需要筛选或排序的字段单独建列。
- 所有时间统一存储 UTC，接口返回 ISO-8601；前端按用户时区显示。
- 删除策略默认软删除记忆和用户；日记删除需要触发来源记忆与向量补偿任务。

### 6.3 MyBatis 规范

Mapper 接口只暴露业务需要的查询，XML 负责复杂 SQL、动态条件和结果映射。查询返回 Entity 或 Query DTO，Controller 只返回 Response DTO。

```java
@Mapper
public interface DiaryMapper {
    Diary selectByIdAndUserId(@Param("id") Long id,
                              @Param("userId") Long userId);

    List<Diary> selectPage(DiaryQuery query);

    int insert(Diary diary);

    int updateByIdAndUserId(Diary diary);

    int deleteByIdAndUserId(@Param("id") Long id,
                            @Param("userId") Long userId);
}
```

XML 中禁止 `SELECT *`、手工拼接用户输入和省略 owner 条件。分页统一使用 `page`、`size`，并在 Service 层限制 `size <= 100`。

## 7. 认证、安全和隐私

### 7.1 认证方案

第一版选择 HttpOnly、Secure、SameSite Cookie 保存会话 Token；若部署环境不支持 Cookie，再切换为短期 Access Token + Refresh Token。认证方式必须全项目统一，不能让每个接口自行决定。

认证接口：

- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/logout`
- `GET /api/auth/me`

密码使用 BCrypt 或 Argon2 哈希。登录失败使用统一错误信息，避免暴露用户名是否存在。受保护接口未登录返回 `40101`，无资源权限返回 `40301` 或统一 `40401` 以避免资源枚举。

### 7.2 数据保护

- 日记正文使用服务端 AES-256-GCM；密钥由环境变量注入，不写数据库和代码。
- 日志禁止输出正文、Token、Cookie、API Key 和完整 Prompt。
- 模型调用只发送必要字段；敏感实体脱敏接口预留在 `Sanitizer`。
- 用户可以暂停 AI 分析、导出数据、删除数据和治理记忆。
- 所有 AI 召回先按 `user_id` 过滤，再回 MySQL 校验来源和状态。

## 8. REST API 规范

### 8.1 通用返回和错误码

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": 1730000000000
}
```

| code | 类型 | 说明 |
| --- | --- | --- |
| `40001` | 参数 | 参数缺失、格式或长度错误 |
| `40101` | 认证 | 未登录、Cookie/Token 无效 |
| `40301` | 权限 | 无权访问资源 |
| `40401` | 资源 | 日记、会话或记忆不存在 |
| `40901` | 冲突 | 用户名、幂等键或状态冲突 |
| `42201` | 数据 | AI JSON 或业务状态无法处理 |
| `50011` | AI | 模型或向量服务失败 |
| `50001` | 系统 | 未知系统错误 |

### 8.2 日记和标签

| 方法 | 路径 | 请求要点 |
| --- | --- | --- |
| `POST` | `/api/diaries` | `title, content, mood, weather, location, tagIds` |
| `GET` | `/api/diaries` | `page, size, keyword, from, to, mood, tagId` |
| `GET` | `/api/diaries/{id}` | 返回正文、标签、分析状态 |
| `PUT` | `/api/diaries/{id}` | 只允许当前用户更新 |
| `DELETE` | `/api/diaries/{id}` | 删除正文、关联、分析和向量来源 |
| `GET` | `/api/tags` | 当前用户标签 |
| `POST` | `/api/tags` | 创建或复用同名标签 |
| `DELETE` | `/api/tags/{id}` | 删除未被使用的标签或解除关联 |

分页返回：

```json

  "items": [],
  "page": 0,
  "size": 20,
```

### 8.4 资源权限检查

每个 Controller 从安全上下文取得 `currentUserId`，不接受前端传入的 `userId` 作为权限依据。Service 调用 Mapper 时始终传入该 ID；资源不存在和不属于当前用户的场景不返回敏感差异。

### 9.4 Axios 封装

`src/api/request.ts` 创建唯一 Axios 实例：

- `baseURL` 来自 `VITE_API_BASE_URL`，默认 `/api`。
- 请求自动携带 Cookie，设置 15 秒普通请求超时。
- 响应拦截器检查业务 `code`，统一转换为前端错误对象。
- `40101` 清理用户 Store 并跳转 `/login`。
- 业务错误显示用户可理解的文案，技术细节只写开发日志。

## 10. 前端交互和可用性要求

- 所有异步按钮有 loading 和防重复提交。
- 列表、详情、聊天和记忆中心都有 loading、empty、error 三种状态。
- 删除、禁用和账户清除属于危险操作，必须二次确认并反馈结果。
- AI 消息显示“正在检索/生成”的状态；模型失败保留用户输入并提供重试。
- 日记编辑器支持自动保存草稿（可在 Phase 2 后半实现），离开页面提示未保存内容。
- Markdown/富文本渲染必须进行 XSS 过滤，不能直接把模型输出作为 HTML 注入。
- 键盘导航、表单标签、对比度和移动端布局纳入验收；最小支持 375px 宽度。

## 11. 分阶段开发计划

| Phase | 后端交付 | 前端交付 | 验收 |
| --- | --- | --- | --- |
| 0 | Spring Boot 空项目、MyBatis、迁移、健康检查、Docker | Vue 空项目、路由、Axios、布局 | clone 后能启动并访问健康检查 |
| 1 | User、注册登录、Cookie/JWT、全局异常 | 登录、注册、路由守卫、用户状态 | 未登录 401，用户隔离有效 |
| 2 | Diary CRUD、标签、分页、筛选 | 列表、编辑器、详情、标签筛选 | 无 AI 也能完成日记闭环 |
| 3 | AiClient、分析 DTO、异步 AiTask | 分析状态、摘要、情绪和主题展示 | 模型失败不影响正文保存 |
| 4 | 对话、Recent Memory、上下文预算 | Chat 会话、消息、重试 | AI 能回答近期状态问题 |
| 5 | Embedding、Chroma、权限过滤 | 引用来源和检索状态 | 能召回当前用户历史日记 |
| 6 | Long-term Profile、Memory Center、治理 | 记忆列表、编辑、禁用、删除 | 用户能控制且删除后不再召回 |
| 7 | AES、导出、删除补偿、Redis（可选） | 设置、导出、暂停 AI、账户清除 | 数据治理和恢复路径可验证 |
| 8 | Docker、CI、测试、文档、License | 生产构建、错误页、响应式检查 | 陌生用户按 README 可部署 |

每个 Phase 都要形成可启动、可测试、可提交 Git 的稳定版本，不能把多个阶段的数据库、接口和页面变更集中到最后一次集成。

## 12. 测试和质量门槛

## 13. Docker 和环境变量

### 13.1 服务

```text
docker compose
├── mysql
├── chroma
└── backend       # 可选，开发时也可宿主机运行

frontend          # Vite 开发服务器或 Nginx 静态部署
```

Redis 作为第二阶段性能和限流组件，只有在确有缓存/队列需求时加入，不能为了堆栈而默认增加运维负担。

### 13.2 `.env.example`

```dotenv
DB_HOST=localhost
DB_PORT=3306
DB_NAME=ai_diary
DB_USERNAME=ai_diary
DB_PASSWORD=change-me

SERVER_PORT=8080
AUTH_COOKIE_SECURE=false
JWT_SECRET=change-me-in-local-only
DIARY_ENCRYPTION_KEY=base64-encoded-32-byte-key

AI_BASE_URL=
AI_API_KEY=
AI_CHAT_MODEL=
AI_EMBEDDING_MODEL=
AI_ANALYSIS_ENABLED=false

VECTOR_STORE=chroma
VECTOR_DB_URL=http://localhost:8000

VITE_API_BASE_URL=http://localhost:8080/api
```

真实值禁止提交；CI 使用 GitHub Secrets，生产环境使用独立密钥管理和 HTTPS。

### 13.3 启动顺序

1. 复制 `.env.example` 为 `.env` 并填写本地数据库配置。
2. 执行 `docker compose up -d mysql chroma`。
3. 进入 `backend` 执行 `./mvnw spring-boot:run`。
4. 进入 `frontend` 执行 `npm install`、`npm run dev`。
5. 访问前端，注册账户，创建日记，检查任务和分析状态。
6. 配置 AI Provider 后，再验证 Chat、Embedding 和 Memory Center。
