## 一、一句话定位

**我是这个项目"产品的骨架和皮肤"：从数据库迁移、Spring Boot 分层、MyBatis SQL、Cookie 认证、REST 契约，一直到 Vue 3 的 9 个页面和 Pinia 状态，全部由我交付；另一个人负责"大脑"（AI Agent、Prompt、三层记忆规则、向量检索）。**

判定标准很简单：**凡是用户能在浏览器里点到的、凡是需要带 `user_id` 去查数据库的，都是我的活。** 凡是需要调用大模型和向量库做判断的，是他的活。

## 二、我需要交付的 9 个后端模块（前后端文档 §5.1）

| 模块 | 我要写的核心类 | 关键规则 |
| --- | --- | --- |
| Auth | `AuthController`、`AuthService`、`UserMapper` | 注册/登录/退出/me；BCrypt 或 Argon2；登录失败统一文案 |
| Diary | `DiaryController`、`DiaryService`、`DiaryMapper` | CRUD、分页、日期/关键词/心情/标签筛选；**AES-256-GCM 加密正文**；发布 `DiaryCreatedEvent` |
| Tag | `TagController`、`TagService`、`TagMapper` | 同名标签复用；`(user_id, name)` 唯一 |
| AI | `AiChatController` | 会话/消息 CRUD、发送消息；**服务层调用他写的 `AiChatService`** |
| Memory | `MemoryController`、`MemoryService` | 列表/改/禁用/启用/删除；删除要**同步通知向量库** |
| Profile | `UserProfileController`、`UserProfileService` | 画像读取 + 用户手动 PATCH（标 `MANUAL`，模型不得覆盖） |
| Task | `AiTaskService`、`AiTaskWorker`、`AiTaskRetryPolicy` | 幂等键、状态机、重试、错误码落库 |
| Export | `ExportController`、`ExportService` | JSON/ZIP 导出、账户清除 |
| Common | 统一响应 `Result<T>`、全局异常、错误码枚举、`CurrentUserId` 解析 | 见 §4 |

### 严格的分层纪律（文档 §3.1，会被 review 的点）

- **Controller**：参数校验（`@Valid`）、取 `currentUserId`、调 Service、包统一响应。禁止写 SQL、禁止碰 Prompt、禁止直接调模型。
- **Service**：业务规则、权限、事务、事件发布。禁止返回 HTTP 状态细节。
- **Mapper**：只做 SQL 和映射。**禁止先按 ID 查全表再在 Java 内存里过滤 `userId`。**
- **所有 SQL 显式带 `user_id`**：更新删除必须是 `WHERE id = #{id} AND user_id = #{userId}`。
- **XML 禁止 `SELECT *`**、禁止字符串拼接用户输入（只用 `#{}`）。
- 分页统一 `page` / `size`，**Service 层强制 `size <= 100`**。

### 页面职责与**必须处理的四态**（loading / empty / error / 进行中）

| 页面 | 主要功能 | 必须处理的状态 |
| --- | --- | --- |
| Dashboard | 今日记录状态、最近心情、AI 洞察 | loading、空数据、分析失败 |
| DiaryList | 日期/关键词/标签/心情筛选 + 分页 | 查询中、无结果、分页边界 |
| DiaryEditor | 正文、心情、标签、草稿 | 保存中、未保存离开提示、校验错误 |
| DiaryDetail | 正文、AI 分析、来源记忆、任务状态 | 分析进行中、失败重试 |
| MemoryCenter | 查看/修改/固定/禁用/删除记忆 | 删除二次确认、撤销提示、来源跳转 |
| AiChat | 会话、消息、引用来源、重新发送 | 发送中、超时、空会话 |
| Profile | 长期画像 + 近期状态 | AI/手动来源区分、保存冲突 |
| Settings | AI 开关、导出、删除账户、主题 | 危险操作确认与结果反馈 |

### 前端工程纪律

- `src/api/request.ts` 是**唯一** Axios 实例：`baseURL` 取自 `VITE_API_BASE_URL`（默认 `/api`）、自动带 Cookie、普通请求 15s 超时、响应拦截器检查业务 `code` 并转成前端错误对象、**`40101` 清空 user store 并跳 `/login`**。
- 页面只做展示和交互；API 调用集中在 `src/api/*`；跨页面状态进 Pinia（`user` / `diary` / `ai` / `app`），**页面临时表单不进 Store**。
- 重复逻辑抽到 `composables/`（如 `useAsyncState`、`usePagination`、`useAiTaskPolling`）。
- 所有异步按钮 loading + 防重复提交；删除/禁用/清账户必须二次确认。
- AI 消息要有"正在检索/生成"状态；模型失败**保留用户输入**并可重试。
- 模型输出渲染必须 XSS 过滤（Markdown 渲染器白名单），**禁止 `v-html` 直出模型文本**。
- 响应式最小支持 **375px**，桌面验收 1440px；键盘导航、表单 label、对比度纳入验收。

## 四、必须先冻结的 6 项契约（否则后面返工最惨）

这些字段一旦定下来，前后端和 AI 侧三边都要遵守。**建议在写代码前和对方开一次 30 分钟对齐会，产出 `docs/api.md` 草稿。**

1. **统一响应体**：`{ code, message, data, timestamp }`。
2. **错误码字典**：`40001` 参数 / `40101` 未登录 / `40301` 无权限 / `40401` 资源不存在 / `40901` 冲突（用户名、幂等键、状态）/ `42201` 无法处理 / `50011` AI 或向量服务失败 / `50001` 未知。
3. **分页返回体**：`{ items, page, size, total, hasNext }`，`page` 从 **0** 开始。
4. **时间格式**：数据库统一存 **UTC**，接口返回 **ISO-8601**，前端按用户时区显示。
5. **认证方式**：第一版 **HttpOnly + Secure + SameSite Cookie**（若部署环境不支持 Cookie，再整体切 Access + Refresh Token，**不允许接口各自决定**）；受保护接口未登录 `40101`，无权资源返回 `40301`/`40401` 且**不泄露资源是否存在**。
6. **命名与类型对齐**：`recent_state`/`long_term_facts`/`citations`/`used_memory_ids` 等字段以 AI 文档 §5.3 与 §7.2 的 JSON 为唯一真源，前端 `src/types/` 一一镜像，禁止自己改名。

## 七、Java 侧对接边界（我给壳，他填肉）

这是双人协作最容易扯皮的地方，建议**由我定义接口签名，他实现**，并让他只依赖 `AiClient` / `VectorStore` 这两个接口，方便 Mock。

```java
// 我定义并装配（Spring Bean / 配置读取），他实现或实现+我注册
AiClient                      // 隔离 LangChain4j，便于测试和换供应商
PromptService                 // 版本化 Prompt：system/developer/context/user 四层
CognitionService.analyze()    // 日记 -> DiaryAnalysis(JSON DTO)
MemoryAgentService.apply()    // 写/更新三层记忆，返回 MemoryChangeSet
EmbeddingService.index()      // 切分 + 写向量
RetrievalAgentService.retrieve() // query embedding + filter + Top-K=8 重排
ResponseAgentService.answer()    // 依据上下文生成 ChatAnswer + citations
VectorStore (interface)        // MVP: ChromaVectorStore
```

**我负责的框架部分（他不管，但没它跑不起来）：**
- `DiaryCreatedEvent` + `@TransactionalEventListener(phase = AFTER_COMMIT)`（或事务型 Outbox）——**日记保存在同一事务内，模型调用在事务外异步执行**，避免 Worker 读到未提交数据和长事务。
- `AiTask` 全生命周期：`PENDING -> RUNNING -> SUCCESS / FAILED -> RETRYING -> RUNNING`，`PENDING/RUNNING -> CANCELLED`；任务唯一键幂等；超最大重试保持 `FAILED`，等用户/管理员显式重试。
- 重试策略：连接超时 5s / 读取超时 30s / 单任务最多 3 次；**只对网络错误、429、5xx 指数退避**，4xx 参数错误不重试；JSON 校验失败先发一次修复请求再失败。这些值全部走环境变量。
- 失败可观察：`ai_task.error_code` + 前端"重试"按钮（`POST /api/ai/diaries/{id}/analyze`）。
- 补偿任务：删日记时清理 analysis / 来源记忆 / 向量，失败落补偿任务而不能静默成功。

**我必须守住的隐私线（AI 文档 §11）：**
- 日志/metrics **禁止**出现日记正文、Prompt 全文、Token、Cookie、API Key。
- 正文 AES-256-GCM 存库，给 AI 前解密，**只发最小必要内容**；`Sanitizer` 接口预留。
- 用户关闭 AI 分析后不再创建新认知任务。
- Prompt Injection 只影响模型输入，**不能改变服务端权限、SQL、任务状态或工具白名单**。

3. **`service/ai` 与 `service/memory` 的接口签名**：由我定义（§7），他实现；两边都只依赖 `AiClient`、`VectorStore` 接口，保证没 API Key 时用 Mock 也能跑通注册/日记/前端全流程。
4. **谁写 `/api/diaries/{id}/analysis`、`/api/ai/tasks/{id}`、`/api/memories/*` 这几个 Controller**：两份文档都提到了，容易双写。**建议归我**（我负责 HTTP 契约与权限），他只暴露 Service 方法。
5. **联调开关**：`AI_ANALYSIS_ENABLED`、`VECTOR_STORE=chroma` 等环境变量由我读取并注入；约定好"没 Key 时前端展示什么"（分析状态置灰 / 显示"AI 未启用"而不是报错）。

## 十二、最容易踩的 8 个坑（提前避开）

1. **先查全表再 Java 过滤 user_id** —— 文档明令禁止，且会导致跨用户泄露，必须写在 XML 的 `WHERE`。
2. **把模型调用塞进数据库事务里** —— 事务长时间持有 + Worker 读到未提交数据，必须 `AFTER_COMMIT` 事件 + 事务外调用。
3. **一次事务里做部分写入** —— AI 文档 §5.3 规定 JSON 解析失败/字段缺失/超限**整体判失败，不做部分写入**。
4. **`v-html` 直接渲染模型输出** —— XSS 高危，必须过滤。
5. **删除记忆只删 MySQL 不删向量** —— 会造成"删了还能被召回"，必须同步 + 补偿任务。
6. **前端自作主张传 `userId`** —— 权限一律服务端从上下文取。
7. **错误码自行发明** —— 前后端和 AI 三边必须共用同一张码表。
8. **每个接口自己决定认证方式** —— 第一版全项目统一 Cookie 方案。
