## 0. 本项目的实际分工（已确认）

| 角色 | 负责范围 | 交付边界 |
| --- | --- | --- |
| **你（我服务的对象）** | 前后端全部模块 | 决定需求、验收成果、对接同学、把握进度 |
| **我（AI Agent）** | 前后端全部代码的实际编写 | 按模块交付可运行代码 + 测试方法，**每个模块停下来等你验证** |
| **你的同学** | AI 模块（Cognition / Memory / Embedding / Retrieval / Response / Governance） | 我给他定义接口，他填实现 |

**关键结论**：因为这个项目只有你一个人在写前后端代码，所以**不存在"两个人抢同一个文件"的问题**。真正需要对齐的只有一件事 —— **你和同学之间的 Java 接口契约**。

## 1. 核心工作循环（每个模块都走这个循环）

这是你要求的"开发完一个模块就停下来告诉你测试一下"的标准化流程。**每次我都严格执行，不会连着做完三个模块才让你测。**

```text
┌─────────────────────────────────────────────────────────────┐
│  第 1 步：我说明本模块要做什么                                │
│    - 模块目标、涉及的表、涉及的接口、预计文件数                │
│    - 你确认「开始」                                          │
├─────────────────────────────────────────────────────────────┤
│  第 2 步：我写代码                                            │
│    - 迁移脚本 → Entity → Mapper + XML → Service → Controller  │
│    - 同步写单元测试                                          │
├─────────────────────────────────────────────────────────────┤
│  第 3 步：我自检（不通过不交给你）                            │
│    - 编译通过                                                │
│    - 单元测试全绿                                            │
│    - 启动成功                                                │
├─────────────────────────────────────────────────────────────┤
│  第 4 步：🛑 我停下来，交给你一份「验收单」                    │
│    - 需要你执行的确切命令                                     │
│    - 预期看到的结果（正常情况）                               │
│    - 故意造错的验证方法（证明失败路径也对）                    │
│    - 常见报错与对应原因                                       │
├─────────────────────────────────────────────────────────────┤
│  第 5 步：你实测                                             │
│    - 通过 → 告诉我「过了」，我进入下一个模块                   │
│    - 不通过 → 把报错/截图给我，我修完再交一次                  │
└─────────────────────────────────────────────────────────────┘
```

### 为什么要有"故意造错的验证方法"

只验证正常路径，等于没验证。每个模块我都会给你**至少一条失败路径的测试方法**，例如：

- 认证模块：拿 A 的 Cookie 去删 B 的日记，应该返回 404 而不是 200。
- 异步任务模块：把 `AI_API_KEY` 改成一个错误值，日记应该**照常保存成功**，只有任务标 `FAILED`。

这几秒钟的动作，能挡掉 80% 的后期事故。

## 2. 验收单长什么样

每次停下来，我会给你一张这样的表（这是模板，实际内容随模块变化）：

```markdown
## 模块 N：XXX —— 验收单

### 一、启动
命令：cd backend && ./mvnw spring-boot:run
预期：控制台出现 "Started AiDiaryApplication in x.x seconds"，端口 8080

### 二、正常路径验证
| # | 操作 | 预期结果 |
|---|------|---------|
| 1 | POST /api/xxx 带合法参数 | code=0，data 里有 id |
| 2 | GET /api/xxx/{id} | 返回刚才创建的数据 |

### 三、失败路径验证（重要）
| # | 操作 | 预期结果 |
|---|------|---------|
| 3 | GET /api/xxx/999999（不存在的 id） | code=40401，HTTP 404 |
| 4 | 不带 Cookie 请求 | code=40101，HTTP 401 |

### 四、数据库验证
命令：docker exec -it mysql mysql -uroot -p ai_diary -e "select * from xxx"
预期：看到刚插入的行，user_id 正确

### 五、常见报错
| 报错 | 原因 | 解决 |
|------|------|------|
| Port 8080 already in use | 端口占用 | 改 SERVER_PORT 或 kill 进程 |
| Table 'xxx' doesn't exist | 迁移没跑 | 检查 Flyway 日志 |

### 六、如果通过
回复「模块 N 过了」→ 我进入模块 N+1
```

**你有三种回复方式**，我都会正确处理：

| 你说 | 我的动作 |
| --- | --- |
| 「过了」/「OK」 | 直接进入下一个模块 |
| 「这里报错了：<粘贴内容>」 | 定位并修复，重新交一次验收单 |
| 「先跳过，继续下一个」 | 标记为待验证，**在文档里留 TODO**，继续推进（但要提醒你风险） |

## 3. 模块拆分顺序（1 个月节奏）

按 4 周、每周约 5 个工作日排。**里程碑 M1/M2/M3 是可以对外演示的节点。**

### 第 1 周 —— 地基与认证（里程碑 M1：能登录的壳子）

| 模块 | 内容 | 停下来验收什么 |
| --- | --- | --- |
| **0-1** | 仓库结构、`.gitignore`、`.env.example`、`docker-compose.yml`（MySQL + Chroma） | `docker compose up -d` 起来，MySQL 能连上 |
| **0-2** | Spring Boot 骨架、MyBatis 配置、Flyway、统一响应体、全局异常、健康检查 | 访问 `/actuator/health` 返回 UP |
| **0-3** | Vue 3 骨架、路由、Axios 封装、AppShell 布局、Element Plus 接入 | `npm run dev` 打开首页不报错，路由能跳 |
| **1-1** | `V1__init.sql`：user / diary / tag / diary_tag 四张表 | 进数据库看到表结构 |
| **1-2** | 注册接口 + BCrypt + 参数校验 | Postman 注册成功，密码在库里是 `$2a$...` |
| **1-3** | 登录 + HttpOnly Cookie 会话 + `/api/auth/me` | 登录后带 Cookie 能拿到自己的信息 |
| **1-4** | Spring Security 配置 + 401/403 统一处理 | 不带 Cookie 访问受保护接口返回 40101 |
| **1-5** | 前端登录页 + 注册页 + 路由守卫 + user store | 浏览器里能注册、登录、刷新页面仍保持登录 |

### 第 2 周 —— 日记闭环 + 异步框架（里程碑 M2：不接 AI 也能用的日记本）

| 模块 | 内容 | 停下来验收什么 |
| --- | --- | --- |
| **2-1** | AES-256-GCM 加解密工具 + 配置 | 库里是密文，接口返回是明文 |
| **2-2** | 日记创建 + 标签关联 | 能建日记、能打标签 |
| **2-3** | 日记列表 + 分页 + 关键词/日期/心情/标签筛选 | 各种筛选组合都正确，`size=1000` 被拒 |
| **2-4** | 日记详情 + 修改 + 删除（soft delete） | owner 条件生效，A 改不了 B 的 |
| **2-5** | 标签 CRUD | 同名标签复用不重复插入 |
| **2-6** | 前端列表页 + 编辑器 + 详情页 + 标签筛选 | 浏览器里完整走通增删改查 |
| **3-1** | `ai_task` 表 + 状态机 + 幂等键 + 重试策略 | 同一篇日记重复提交不会产生两条任务 |
| **3-2** | `DiaryCreatedEvent` + `AFTER_COMMIT` 监听 + 异步 Worker | 保存日记接口 100ms 内返回，任务异步变 RUNNING→SUCCESS |
| **3-3** | Mock `AiClient` + 任务查询接口 | **没有 API Key 也能看到任务成功** |
| **3-4** | 前端分析状态展示 + 轮询 + 失败重试按钮 | 页面能看到"分析中"→"已完成" |

### 第 3 周 —— 接真实 AI + 对话（里程碑 M3：AI 能回答你的日记）

| 模块 | 内容 | 停下来验收什么 |
| --- | --- | --- |
| **4-1** | LangChain4j 接入 + 依赖版本对齐 + `@AiService` | 应用能启动，调用一次真实模型返回文本 |
| **4-2** | Prompt 四层模板 + `PromptService` 版本化 | Prompt 从 `resources/prompts/` 加载 |
| **4-3** | 结构化输出 DTO + JSON 校验（越界/缺字段/超长） | 模型返回垃圾 JSON 时任务 FAILED 且不部分写入 |
| **4-4** | `diary_analysis` 表 + 分析结果接口 | 能查到摘要、情绪、主题、实体 |
| **4-5** | `ai_conversation` / `ai_message` 表 + 会话 CRUD | 会话和消息能持久化 |
| **4-6** | 上下文组装 + 发送消息接口 + 超时错误码 | 模型超时返回 `50011`，前端保留输入可重发 |
| **4-7** | 前端 Chat 页 + 消息流 + "正在生成"状态 | 浏览器里能对话 |

### 第 4 周 —— 记忆、检索、治理与工程化

| 模块 | 内容 | 停下来验收什么 |
| --- | --- | --- |
| **5-1** | `memory` / `user_profile` 表 + Memory Service 规则 | 低置信度不写长期记忆 |
| **5-2** | Embedding 接入 + Chroma `VectorStore` 实现 + 向量写入 | Chroma 里能看到向量，metadata 带 userId |
| **5-3** | 检索 + Top-K 重排 + 关系库二次校验 + 引用来源 | 能召回自己的历史，**跨用户召回 0 条** |
| **6-1** | 记忆列表接口 + 前端 MemoryCenter 页 | 能查看、编辑记忆 |
| **6-2** | 禁用/启用/删除 + 向量同步 | 删除后 Chroma 里也查不到 |
| **6-3** | Profile 页 + 手动修改标记 MANUAL | 手动改过的记忆不被模型覆盖 |
| **7-1** | 导出（JSON/ZIP）+ 账户清除 | 导出内容不含密钥 |
| **7-2** | 删除日记的补偿任务 | 删日记后 analysis/记忆/向量都没了 |
| **8-1** | Docker 化后端、README、docs、CI | 陌生人按 README 能部署 |
| **8-2** | 测试补齐 + Playwright 全流程 + 响应式 | 375px/1440px 都不溢出 |

**如果时间不够，砍的顺序**（从后往前砍，前面的不能动）：
`8-2` → `7-1` → `using-git-worktrees` 相关 → `6-3` → `5-3` 的重排优化。
**绝对不能砍**：认证、日记 CRUD、异步任务框架、跨用户隔离、删除同步。

## 4. 我什么时候必须停下来问你

除了每个模块的固定验收点，遇到以下情况我会**立即停下来**，不擅自决定：

| 情况 | 为什么必须问 |
| --- | --- |
| 文档本身有歧义或两份文档冲突 | 你的文档就是真源，不能我猜 |
| 需要引入文档没提到的第三方库 | 加依赖是技术决策，且可能影响同学那边 |
| 发现某个设计有问题，需要改表结构 | 表结构变更会传导到前端和 AI 侧 |
| 涉及要花的钱（API 额度、服务器） | 你的钱 |
| 需要你同学的接口才能继续 | 我不替他做决定，也不假装他能马上提供 |
| 测试连续失败 3 次修不好 | 说明我的假设错了，需要你提供真实报错环境 |

**我不会**因为"这个实现更好看"就擅自偏离文档。文档没写的地方，我会**给出 2-3 个选项和推荐**让你选，而不是自己拍。

## 6. Git 工作流（我执行，你确认）

```text
main                  ← 只有通过验收的代码才能进
 └── feat/phase1-auth        ← 每个模块一个分支
 └── feat/phase2-diary-crud
 └── fix/login-cookie-issue
```

**每个模块完成后的动作：**

```bash
git checkout -b feat/phase1-auth
# ... 写代码 ...
git add -A
git commit -m "feat(auth): 注册登录与 Cookie 会话

- V1__init.sql 建 user 表
- AuthService 实现 BCrypt 哈希与登录校验
- SecurityConfig 统一 40101/40301 处理
- 前端登录页 + 路由守卫

验收：见验收单模块 1-2 / 1-3"
git push -u origin feat/phase1-auth
# 你验收通过后，我再合并到 main
```

**提交信息前缀**（文档 §12.3 要求）：`feat` / `fix` / `refactor` / `docs` / `test` / `chore`

**我绝不会做的事**：`git push --force`、直接往 `main` 提交、提交 `.env`、提交 `target/` 或 `node_modules/`。

## 8. 和同学的接口对齐流程

这是本项目**唯一的协作风险点**。流程如下：

```text
第 1 步（Phase 0 期间）：我产出 docs/ai-interface.md
   - 我定义接口签名：AiClient、VectorStore、CognitionService 等
   - 明确每个方法的入参 DTO、出参 DTO、异常约定
   - 你拿给同学确认

第 2 步：同学确认或提修改意见
   - 有意见 → 你转达给我，我改，重新出一版
   - 没意见 → 锁定，之后只增不改

第 3 步（Phase 3-4 期间）：我提供 MockAiClient 实现
   - 返回文档 §5.3 规定的固定合法 JSON
   - 同学的真实实现完成后，通过 Spring Profile 或配置切换

第 4 步：联调
   - 切换配置 → 跑真实模型 → 对不上的地方按接口文档裁决
```

**我给你的保障**：**在同学一行代码都没写的情况下，你也能把 Phase 0 到 Phase 2 全部做完并验收。** 因为 AI 侧全部走 Mock。这是文档里"本地开发先使用固定测试模型或 Mock AiClient"的要求，也是让你不被同学卡住的关键。

**如果同学迟迟没进度**：告诉我，我可以把 `service/ai/` 下的**最小可用实现**也写出来（能调通 DeepSeek、能返回结构化 JSON），让他后续替换。这样你的项目不会因为别人而烂尾。

## 10. 时间投入的实话

1 个月做完 Phase 0-8 是**紧的**。参照物：

| 阶段 | 我的编码时间 | 你的验证时间 |
| --- | --- | --- |
| Phase 0-1（地基+认证） | 中 | 少（看命令输出就行） |
| Phase 2（日记闭环） | 多 | 中（要真在页面上点） |
| Phase 3（异步+Mock） | 中 | 中 |
| Phase 4（真实 AI） | 多 | **多**（调 Prompt 很费时间） |
| Phase 5（向量检索） | 多 | 多（跨用户测试要仔细） |
| Phase 6-7（治理+安全） | 中 | 中 |
| Phase 8（工程化） | 中 | 少 |

**最可能超时的两个地方**，提前说：
1. **Phase 4 调 Prompt** —— 模型输出格式不稳定，可能要来回改好几轮。我会用"JSON 校验 + 一次修复请求"兜住，但不能保证一次成功。
2. **Phase 5 向量检索效果** —— 召回质量取决于 Embedding 模型和切分策略，可能要调参数。

**如果时间紧，我建议的顺序是**：先把 Phase 0-6 做完整（这是能演示、能写进简历的闭环），Phase 7-8 视剩余时间做。**不要为了做完 8 个 Phase 而让前面每个阶段都半成品。**
