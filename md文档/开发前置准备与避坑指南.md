# AI 日记系统 —— 开发前置准备与协作避坑指南

> 用途：**正式写业务代码之前**，我和另一位开发者（AI Agent 方向）必须先一起做完的事，以及开发全程最容易翻车的地方。
> 配套文件：`我的职责与任务清单.md`（职责边界）、`前后端开发文档正式.md`、`AI-Agent-开发文档z han.md`

## 第一部分：开工前必须一起干完的 8 件事

> 顺序很重要。**第 1、2 件事没做完就动手写代码，后面大概率返工。**

### ① 开一次"契约冻结会"（1–2 小时，最高优先级）

会议唯一产出：把下面这张表填满，写进 `docs/api.md` 草稿并提交 Git。**定下来之后只允许新增，不允许改名。**

| 项目 | 待冻结内容 | 建议默认值 |
| --- | --- | --- |
| 统一响应体 | 字段名与嵌套 | `{ code, message, data, timestamp }` |
| 错误码字典 | 12 个码的含义 | 见下方 §2.1 |
| 分页 | 参数名与返回体 | 入参 `page`/`size`，**`page` 从 0 开始**；出参 `{items, page, size, total, hasNext}`；`size <= 100` |
| 时间 | 存储与传输 | 库里 UTC，接口 ISO-8601，前端按用户时区显示 |
| 认证 | 全项目唯一方案 | HttpOnly + Secure + SameSite Cookie；不支持的部署环境再整体切换 |
| 命名风格 | JSON 字段 | 统一 `snake_case`（与 AI 文档 §5.3/§7.2 对齐），Java 侧用 `@JsonProperty` 或全局命名策略 |
| 空值与可选 | null 还是省略 | 统一返回 `null`，不省略字段（前端类型好写） |
| 版本前缀 | 是否 `/v1` | 第一版不加，路径统一 `/api/...` |

**同一次会议还要定死三件"归属"问题：**
1. 谁写 `/api/diaries/{id}/analysis`、`/api/ai/tasks/{id}`、`/api/memories/*` 的 Controller（两份文档都写了 → 建议归我）。
2. AI 相关 5 张表（`diary_analysis` / `memory` / `user_profile` / `ai_conversation`+`ai_message` / `ai_task`）的**字段级约束和索引需求由他提供**，**迁移脚本由我写**。
3. `service/ai/`、`service/memory/` 的**接口签名由我定义**（`AiClient`、`VectorStore` 两个接口优先），他实现。

### ② 技术选型一次性拍板（避免两套写法混在一起）

| 决定项 | 备选 | 必须现在定，因为… |
| --- | --- | --- |
| 前端 UI 方案 | Element Plus **或** Tailwind（文档写的是"或"） | 混用会导致样式和组件重复实现，返工量极大 |
| 包管理器 | npm / pnpm | lockfile 不同会让双方 CI 结果不一致 |
| Node 版本 | 建议 LTS 20 或 22 | 写进 `.nvmrc` + `package.json` 的 `engines` |
| 迁移工具 | Flyway **或** Liquibase | 只允许一套，且只允许我建表 |
| 密码哈希 | BCrypt **或** Argon2 | 混用会导致老账号登不上 |
| 本地向量库 | Chroma（Docker） | 他需要它跑 Embedding，我需要它跑删除补偿联调 |
| Embedding 模型 + 向量维度 | **一次性定死** | ⚠️ 后面换模型 = 全量重嵌入 + 维度不兼容，是隐蔽大坑 |
| 是否启用 TypeScript strict | 建议开 | 后期开启要改一堆文件 |

### ③ 仓库与骨架先跑通（Phase 0 的真正含义）

目标：**双方各自 clone 下来，三条命令能起服务。**

```bash
docker compose up -d mysql chroma
cd backend && ./mvnw spring-boot:run
cd frontend && npm install && npm run dev
```

第一次提交必须包含：`.gitignore`（`.env` / `target/` / `node_modules/` / 日志）、`.env.example`、`docker-compose.yml`、`README.md` 起步版、`docs/` 目录。

**`.gitignore` 里漏掉 `.env` 是最高危的低级错误** —— 里面有 `AI_API_KEY`、`JWT_SECRET`、`DIARY_ENCRYPTION_KEY`。第一次 push 前一定要 `git status` 逐个确认。

### ④ 统一环境变量真源

环境变量是**两份文档的交叠区，也是冲突高发区** —— 我们共用同一个 `application.yml`。

建议：把 AI 相关配置**独立成 `application-ai.yml`**，双方约定"改自己的文件，不动对方的"。`application.yml` 的改动需要提前打招呼。

一次配齐这些（双方都要能读）：

```dotenv
# 数据库 / 服务
DB_HOST=localhost
DB_PORT=3306
DB_NAME=ai_diary
DB_USERNAME=ai_diary
DB_PASSWORD=change-me
SERVER_PORT=8080

# 认证 / 加密
AUTH_COOKIE_SECURE=false
JWT_SECRET=change-me-in-local-only
DIARY_ENCRYPTION_KEY=base64-encoded-32-byte-key

# AI（他主用，我需要读取开关状态）
AI_BASE_URL=
AI_API_KEY=
AI_CHAT_MODEL=
AI_EMBEDDING_MODEL=
AI_CONNECT_TIMEOUT_MS=5000
AI_READ_TIMEOUT_MS=30000
AI_MAX_RETRIES=3
AI_ANALYSIS_ENABLED=false
AI_CONTEXT_TOKEN_BUDGET=6000

# 向量库
VECTOR_STORE=chroma
VECTOR_DB_URL=http://localhost:8000

# 前端
VITE_API_BASE_URL=http://localhost:8080/api
```

### ⑤ 把"没有 API Key 也能开发"变成硬约定（最容易被忽略）

**这是双人项目最常见的阻塞点**：他有 Key 我没 Key，或者 Key 额度用完了，我的注册/日记/前端全流程就测不了。

开工前必须一起做：
- 他提供 `MockAiClient`（返回固定合法 JSON），并保证 `AI_ANALYSIS_ENABLED=false` 时**整个应用能正常启动**。
- 约定：CI 里**永远不允许出现真实 Key**，所有测试走 Mock。
- 约定：Key 没配时 `GET /api/diaries/{id}/analysis` 返回一个明确的业务码（建议 `50011` 或专门状态），**前端显示"AI 未启用"而不是红色报错**。
- 约定：本地固定测试模型/Mock 优先，真实模型联调通过环境变量显式开启。

### ⑥ CI 里加一条"防跨用户泄露"的自动化测试（安全基线）

在写业务之前就把测试骨架搭上，后面每个接口自动被覆盖：

> 用户 A 请求用户 B 的任务 / 会话 / 记忆 / 向量 → 一律 403 或 404，且**响应体不能泄露"资源是否存在"的差异**。

这条测试挂到 CI 上，比事后 Review 有效一百倍。同理再挂一条 Prompt Injection 测试（日记里写"忽略之前指令"），验证服务端权限、SQL、任务状态、工具白名单都不变。

### ⑦ 团队约定落地（半天内搞定，长期省事）

- **分支策略**：`main` 保护（禁止直接 push）+ `feat/*`、`fix/*` 短生命周期分支。
- **提交规范**：`feat` / `fix` / `refactor` / `docs` / `test` / `chore` 前缀。
- **PR 模板**：接口契约 ✓ 权限条件 ✓ 数据库迁移 ✓ 异常状态 ✓ 测试 ✓ 文档 ✓ 回滚方式 ✓（就是文档 §12.3 的提交门槛，做成 checklist）。
- **CODEOWNERS**：`service/ai/`、`service/memory/` 归他，其余归我。避免互相覆盖。
- **接口集合**：建一份 Postman / Bruno collection 提交到仓库，双方联调共用，避免"你说的字段和我理解的不一样"。

### ⑧ 里程碑与联调窗口

- 按 Phase 0–8 排期，**每个 Phase 结束时必须形成"可启动、可测试、可提交 Git"的稳定版本**（文档明令禁止把多阶段变更堆到最后一次集成）。
- 约定**每个 Phase 末做一次联调**，Phase 3/4/5/6 是三个人的接口交叠区，联调必须提前约时间。
- 每个 Phase 交付时必须带：代码 + 迁移脚本 + 接口说明 + 测试 + **一条可复现的验收命令**。文档明确写了：**不接受只在模型 Playground 里成功的结果**。

## 第二部分：开发前就要知道的坑（按危险度排序）

### 🔴 高危：会造成数据泄露或不可逆损坏

**坑 1｜先按 ID 查全表，再在 Java 内存里过滤 `user_id`**
- 表现：`selectById(id)` 然后 `if (diary.getUserId().equals(currentUserId))`。
- 后果：跨用户数据泄露，且文档**明令禁止**。一旦有人后续加个分支忘了判断，就是事故。
- 正确：`WHERE id = #{id} AND user_id = #{userId}`，写进 XML。

**坑 2｜`.env` 被提交进 Git**
- 里面有 `AI_API_KEY`、`JWT_SECRET`、`DIARY_ENCRYPTION_KEY`。
- 一旦进仓库，即使后面删除，Git 历史里永久留存，Key 必须作废重签。
- 正确：第一条 commit 就带 `.gitignore`，CI 用 GitHub Secrets，本地用 `.env.example` 复制。

**坑 3｜日志里打出日记正文、Prompt 全文、Token、API Key**
- Spring Boot 默认会打 SQL 参数日志，`content_ciphertext` 解密后如果被 log 出去就完了。MyBatis 开 `log-impl` 时要小心。
- 正确：日志只记录 provider、model、耗时、token 用量、任务 ID、错误类别。配一个日志脱敏/白名单规则。

**坑 4｜前端 `v-html` 直接渲染模型输出**
- 模型输出可能包含 `<script>`，直接注入就是 XSS。
- 正确：Markdown 渲染走白名单过滤；模型文本一律当纯文本，引用来源里的日记 ID 由前端映射成路由链接。

**坑 5｜删除记忆只删 MySQL，不删向量库**
- 表现：用户点了删除，前端不显示了，但 AI 还能"想起"这件事并说出来 —— 隐私事故。
- 正确：删除/禁用必须同步向量库；失败落**补偿任务**并记录，**不能静默成功**。删日记同理（正文 + 关联 + 分析 + 来源记忆 + 向量）。

### 🟠 中危：会造成架构返工或脏数据

**坑 6｜把模型调用塞进数据库事务里**
- 后果：事务长时间持有连接 + Worker 读到未提交数据。模型一次调用 30 秒，事务就开 30 秒。
- 正确：日记保存与 AI 任务创建在同一事务；事件用 `@TransactionalEventListener(phase = AFTER_COMMIT)` 或事务型 Outbox 在**提交后**投递；模型调用在**事务外**异步执行。

**坑 7｜AI 分析做"部分写入"**
- 场景：JSON 里 `summary` 有、`entities` 超长 → 只写了 summary。
- 后果：记忆状态不一致，难以排查。文档规定：**JSON 解析失败、字段缺失、超限一律整体判失败，不做部分写入。**

**坑 8｜忘了幂等键，同一篇日记被分析 N 次**
- 正确：`ai_task.idempotency_key` 唯一，键 = `userId + sourceType + sourceId + taskType + version`。同一篇日记的同一种分析版本只能有一个生效任务。用户连点"重试"按钮不能创建多条任务（前端也要防重复提交）。

**坑 9｜重试策略一把梭，4xx 也重试**
- 正确：只对**网络错误、429、5xx** 做指数退避；**4xx 参数错误不重试**；JSON 校验失败先发**一次**修复请求，仍失败则任务失败。超最大重试次数保持 `FAILED`，等用户/管理员显式重试。

**坑 10｜Embedding 模型换了，向量库全废**
- 不同模型的向量维度不兼容，混用会静默返回垃圾结果。
- 正确：开工前定死模型和维度，并在向量 metadata 里存 `model` + `dimension`，检索时校验不匹配就报错而不是硬算。

**坑 11｜`SELECT *` + 手拼 SQL**
- 文档 XML 规范明令禁止。`SELECT *` 在加解密列、JSON 列场景下尤其危险（不小心把密文/大字段读出来）。
- 正确：显式列名，只用 `#{}` 占位符。

**坑 12｜分页 `size` 不设上限**
- 有人传 `size=100000` 就能拖垮数据库。
- 正确：Service 层强制 `size <= 100`。

### 🟡 协作类：不致命但极其消耗时间

**坑 13｜两人共用一个 `application.yml` / `pom.xml`**
- 表现：他加 LangChain4j 依赖，你改 MyBatis 配置，每次 merge 都冲突，还容易把对方配置覆盖掉。
- 正确：AI 配置拆到 `application-ai.yml`；`pom.xml` 改动在 PR 里说明；依赖由我统一引入（避免版本冲突）。

**坑 14｜依赖版本没锁，LangChain4j 与 Spring Boot 3.x 打架**
- LangChain4j 会带 OkHttp / Jackson / Reactor 的传递依赖，和 Spring Boot 的 BOM 冲突时会出 `NoSuchMethodError` —— 而且**编译期不报错，运行期才炸**。
- 正确：Phase 0 就由我把依赖版本一次性对齐（`dependencyManagement` / BOM），并跑一次集成测试验证能启动。

**坑 15｜共用一个 MySQL 实例互相污染数据**
- 表现：他跑测试把表清了，你本地数据没了；或者 Flyway 校验和对不上。
- 正确：本地容器各自一份（compose 里别固定 container_name，或用不同端口/volume）；集成测试用 **Testcontainers 各自起库**；约定**只允许我改迁移脚本**，他需要新表/新列找我加。

**坑 16｜DTO / Entity / VO 混用**
- 表现：Controller 直接返回 `Diary` Entity（把 `content_ciphertext` 甚至 `password_hash` 泄露出去）；或者把 AI 内部 DTO（含 `used_memory_ids`、内部 prompt 痕迹）直接透给前端。
- 正确：Controller **只返回 Response DTO**；AI 内部 DTO 与前端契约 DTO 分开，中间做一层显式映射。

**坑 17｜没有 API Key 时应用起不来，阻塞对方**
- 正确：`AiClient` 必须有 Mock 实现；`AI_ANALYSIS_ENABLED=false` 时应用照常启动、日记照常保存、前端照常可用（只是 AI 区域置灰）。

**坑 18｜前端错误码自行发明 / 只判断 HTTP 状态码**
- 表现：后端返回 HTTP 200 + `code: 40101`，前端只看 HTTP 200 就当成功了。
- 正确：Axios 响应拦截器**必须检查业务 `code`**；`40101` 清空 user store 并跳 `/login`；前后端共用同一张码表。

**坑 19｜前端只信任本地缓存判断登录态**
- 正确：首次打开受保护页面先调 `GET /api/auth/me` 确认；路由守卫不能只看 Pinia 里有没有 token。

**坑 20｜时区不统一**
- 表现：库里存本地时间，接口返回不带时区，前端再 `new Date()` 一转换，日记时间差 8 小时。
- 正确：库里 UTC，接口 ISO-8601（带时区），前端统一用工具函数按用户时区格式化，**禁止在页面里散落 `new Date()` 拼接**。

## 第三部分：交付顺序上的坑

**顺序铁律（来自两份文档的阶段表，别打乱）**

```text
Phase 0 骨架 → 1 认证 → 2 日记闭环（不接 AI！）→ 3 异步任务 → 4 对话
→ 5 RAG → 6 记忆治理 → 7 加密/导出/删除补偿 → 8 工程化
```

**必须守住的三个顺序原则：**

1. **Phase 2 结束前不要碰 AI。** 日记 CRUD、标签、分页筛选、owner 条件必须先在"完全没有 AI"的情况下闭环。这样 AI 出任何问题都不影响主流程，也才符合"模型失败不影响正文保存"的验收标准。
2. **异步框架（Phase 3）必须先于 AI 效果（Phase 4/5）。** 先把 `AiTask` 状态机、幂等、重试、错误码、前端"进行中/失败重试"跑通，**用 Mock 返回固定 JSON 验证整条链路**，再让他接真实模型。反过来做的话，一旦模型不稳定，你分不清是自己的任务框架有问题还是模型有问题。
3. **向量库（Phase 5）先于记忆治理（Phase 6）。** 因为治理的验收标准是"删除后关系库和向量库都不可检索"，得先有向量库才能验证删除同步。

**每个 Phase 的收尾动作（缺一不可）：**
- [ ] 迁移脚本可重复执行（新环境从零跑一遍）
- [ ] 接口说明更新到 `docs/api.md`
- [ ] 测试通过 + 一条可复现的验收命令写进 README/PR
- [ ] 提交一个可启动的稳定版本（能 clone 起来）

### A.3 ⚠️ 问答暴露出来的三个硬性问题

这三点不解决一定会卡住，提前记在这里：

#### 问题 1：DeepSeek 没有 Embedding API

- **现象**：你选了 DeepSeek，但 DeepSeek **只提供 Chat 模型，不提供 Embedding 接口**。
- **影响**：Phase 5 的语义检索必须要有 Embedding 模型，否则"AI 能检索历史日记"这个核心卖点做不出来。
- **解决**：Chat 与 Embedding 做成**两个独立配置项**，可来自不同提供商。推荐补一个国内直连的：

| 提供商 | 模型 | 维度 | 备注 |
| --- | --- | --- | --- |
| 阿里云百炼 | `text-embedding-v3` | 1024 | 推荐，Tlias 那套 AI 课常用，有免费额度 |
| 硅基流动 | `BAAI/bge-m3` | 1024 | 开源模型，也有免费额度 |

- **什么时候必须定**：**Phase 5 开始之前**（约第 4 周）。Phase 0-4 完全不受影响。
- **已做的工程保障**：模型名和维度全部走环境变量；向量 metadata 里存 `model` + `dimension`；检索时维度不匹配**直接抛错**，不静默返回垃圾结果。

#### 问题 2：LangChain4j 的依赖冲突是"运行期才炸"的坑

- **现象**：LangChain4j 带入 OkHttp / Jackson / Reactor，与 Spring Boot 3 的 BOM 冲突时**编译完全正常，启动或调用时才报 `NoSuchMethodError`**。
- **影响**：拖到 Phase 4 才发现，前面的代码可能都要跟着调整。
- **解决**：**Phase 0 模块 0-2 就做一次带 LangChain4j 依赖的空应用启动验证**。花 20 分钟，省后面一整天。
- **附加约束**：只引 `langchain4j` + `langchain4j-open-ai`，**不引** `langchain4j-spring-boot-starter`；所有调用包在 `AiClient` 接口后面，出问题只改一个实现类。

#### 问题 3：你和同学之间唯一的协作风险

- **现象**：只有你写前后端，所以不存在抢文件问题；但**他的 AI 模块如果迟迟没进度，Phase 4/5 就会停摆**。
- **解决**（已写进开发模式文档 §8）：
  1. 我先产出 `docs/ai-interface.md` 定义接口签名，你拿给他确认。
  2. 我提供 `MockAiClient`，返回文档规定的固定合法 JSON。
  3. **结论：在同学一行代码都没写的情况下，你也能独立完成并验收 Phase 0 到 Phase 3。**
  4. 如果他一直没进度，告诉我，我可以把 `service/ai/` 的**最小可用实现**也写出来（能调通 DeepSeek、能返回结构化 JSON），他后续替换即可。**你的项目不会因为别人而烂尾。**

### A.4 关于"1 个月做完"的实话

1 个月做完 Phase 0-8 是**紧的**。最可能超时的两处：

1. **Phase 4 调 Prompt** —— 模型输出格式不稳定，可能要来回改好几轮。
2. **Phase 5 向量检索效果** —— 召回质量取决于 Embedding 模型和切分策略，可能要调参。

**建议的取舍**：先把 **Phase 0-6 做完整**（这是能演示、能写进简历的闭环），Phase 7-8 视剩余时间做。**不要为了做完 8 个 Phase 而让每个阶段都是半成品。**

**可砍顺序**（从后往前）：`8-2 响应式细节` → `7-1 导出` → `6-3 Profile 手动修改` → `5-3 重排优化`

**绝不能砍**：认证、日记 CRUD、异步任务框架、跨用户隔离、删除同步。
